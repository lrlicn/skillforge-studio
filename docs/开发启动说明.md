# 开发启动说明

## 前端

```powershell
cd D:\code\skillforge-studio\frontend
npm install
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。登录与注册均调用真实后端接口，页面刷新后通过 HttpSession 恢复账号状态。

## 后端

后端使用 Java 21、Spring Boot 3.5、MyBatis-Plus、MySQL 8.4 和 Knife4j。本地数据库及 GitHub 凭据统一配置在 `src/main/resources/application-secrets.yml`，该文件已被 Git 忽略。

### 使用 IntelliJ IDEA 构建

1. 在 IDEA 中打开 `D:\code\skillforge-studio\backend\pom.xml`，选择“作为项目打开”或“添加为 Maven 项目”。
2. 将 Project SDK 和 Maven Runner JRE 都设置为 JDK 21。
3. 在 Maven 工具窗口点击“重新加载所有 Maven 项目”。
4. 先运行 Maven 生命周期中的 `clean`，再运行 `package -DskipTests`。
5. 运行 `com.skillforge.studio.SkillForgeStudioApplication`。
6. 默认模式不启用 OAuth，启动成功后访问 `http://127.0.0.1:8080/api/v1/system/health` 和 `http://127.0.0.1:8080/doc.html`。

创建 GitHub OAuth App 并填写 `application-secrets.yml` 后，将 `skillforge.github.oauth-enabled` 改为 `true`，重启后端即可启用 GitHub OAuth。

开发环境可使用：

```powershell
cd D:\code\skillforge-studio\infra
docker compose up -d mysql
```

数据库连接配置位于 `D:\code\skillforge-studio\backend\src\main\resources\application-secrets.yml`；开发环境图片会写入 `D:\code\skillforge-studio\upload`。OAuth 仍需创建 GitHub OAuth App 并填写客户端信息后再联调。

## 创建 GitHub OAuth App

1. 登录 GitHub，点击右上角头像，进入 `Settings`。
2. 左侧进入 `Developer settings` → `OAuth Apps` → `New OAuth App`。
3. 填写以下内容：

   - `Application name`：`SkillForge Studio Local`
   - `Homepage URL`：`http://127.0.0.1:5173`
   - `Application description`：可填写 `本地开发环境的 AI skill 管理平台`
   - `Authorization callback URL`：`http://127.0.0.1:5173/login/oauth2/code/github`

4. 点击 `Register application`。进入应用详情页后复制 `Client ID`。
5. 点击 `Generate a new client secret`，完成 GitHub 验证后复制生成的 Secret。Secret 只显示一次，不要提交到代码仓库或截图公开。
6. 编辑 `backend/src/main/resources/application-secrets.yml`：

```yaml
skillforge:
  github:
    oauth-enabled: true
    client-id: 你的 Client ID
    client-secret: 你的 Client Secret
```

`token-encryption-key` 已在本地私密配置中生成，用于 AES-256-GCM 加密 GitHub Access Token，不要删除、公开或提交该密钥。开发环境的 `/oauth2` 和 `/login/oauth2` 均由 Vite 代理到后端，因此授权回调使用 `5173` 端口，并与平台 Session 保持同源。

7. 保存配置，重启前端开发服务和后端。不再需要设置 Spring Profile 或 PowerShell 密钥环境变量。

若使用私有仓库并需要通过平台提交，当前默认 scope 为 `read:user,user:email,repo`；这会请求仓库读写权限。后续正式部署时应改用更小的权限范围或 GitHub App。

本地前端地址必须与 `Homepage URL` 保持一致，后端回调地址必须逐字符匹配 GitHub 页面中的 `Authorization callback URL`。不要把 `localhost` 和 `127.0.0.1` 混用。

Watt Toolkit/Steam++ 的 GitHub 加速会使用本地 `SteamTools Certificate` 代理 HTTPS，而 JDK 默认不信任该证书。执行 OAuth Token 交换、仓库读取和导入测试前应关闭 GitHub 加速及 `Steam++.Accelerator`，不要通过关闭 Java SSL 校验绕过证书错误。
